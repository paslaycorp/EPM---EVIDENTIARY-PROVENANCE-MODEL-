# EPM v0.1.2 Corrective Release Decision — 2026-09-14

## Decision

Prepare EPM `0.1.2` as a bounded corrective release over `0.1.1`. Do not alter the historical v0.1.1 release commit or its evidence record.

## Trigger

Direct adversarial use of the frozen v0.1.1 public runtime produced executable evidence of four limit failures:

1. caller under-declaration of applicability materiality could authorize an actual context-changing transition;
2. mixed timezone-aware/timezone-naive rule and state timestamps could raise during preservation evaluation;
3. mixed timezone-aware/timezone-naive evidence-availability timestamps could raise during trust evaluation;
4. preservation proof validity lacked an explicit representation of whether externally reported proof claims had been validated at the ingestion boundary.

The four-probe falsification commit is:

`96d47ceb437926a6dda163eff7dc89a6f5eede87`

EPM Runtime CI run `34928796032` failed on both Python 3.12 and 3.13 and reproduced the defects.

## Correction

The corrective runtime:

- derives applicability materiality from actual source/target context and rule changes in addition to caller declaration;
- checks temporal comparability before ordering rule-effective and target-state timestamps;
- checks availability timestamp awareness before ordering availability observations;
- represents ingestion-boundary proof validation separately through `PreservationProof.boundary_validated`;
- prevents boundary-unvalidated proof-shaped input from authorizing a material transition;
- preserves authority-mismatch diagnostics.

## Productization preservation

The original falsification branch was intentionally created from the certified v0.1.1 release commit. Because current `main` contains post-release productization, that branch was not merged directly.

A fresh release candidate was created from current `main` at:

`c85504e2d195adeb51a755bae5a91aa8c78f9071`

Only the verified runtime and adversarial-test delta was transplanted to:

`rc/v0.1.2-corrective`

This preserves the v0.1.1 public landing page, reference examples, reporting surface, and later productization work.

## Verification

Pre-version-metadata release-candidate head:

`97a12463deb4666b1f9ff87bb0b35cc1b8997c25`

EPM Runtime CI run `34929157287` succeeded on Python 3.12 and 3.13, including public examples, certification suite, all four adversarial probes, and distribution build.

A final release-candidate CI run after version/document insertion is required before merge.

## Boundary

This patch does not merge TVC or Variant Hunter and does not expand EPM into a universal external-proof authenticator.

`boundary_validated` records the result of a trust decision made at an ingestion boundary; it does not manufacture that trust decision. External adapters must perform their own legitimate validation procedure before treating externally reported preservation claims as boundary-validated.

FAP-Insurance must be repinned to the exact final v0.1.2 release commit and re-run through its production verification/release chain before FAP production can claim the corrected EPM behavior.
